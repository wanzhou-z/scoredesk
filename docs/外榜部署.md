# 外榜（Outrank）部署

外榜是 ScoreDeck 的第三个能力：把比赛结束那一刻的榜单**冻结**成一份只读存档，再挂到一个长期在线的网站上，供选手和观众回看。

它由两个模块组成：

```text
outrank/
├── archive.py    # 存档 / 解榜 / 重建索引（离线跑，管理员用）
└── outrank.py    # 只读 HTTP 服务：列表页 + 单场榜单页 + 只读 API
```

服务端**没有任何写接口**，只能读取 `archives/` 目录；存档和解榜都是在本地或服务器上手动执行 `archive.py` 完成的。

---

## 一、先跑起来（本机）

```bat
scripts\run-outrank.bat
```

等价于：

```bat
python outrank\outrank.py --host 127.0.0.1 --port 8099 ^
    --archives data\archives --web-root liveboard\web
```

打开 `http://127.0.0.1:8099/` 就能看到外榜列表（没有存档时是空列表）。

参数：

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--host` | `0.0.0.0`（脚本里改成了 `127.0.0.1`） | 监听地址。放在 nginx 后面时保持 `127.0.0.1`。 |
| `--port` | `8080`（脚本用 `8099`） | 监听端口。 |
| `--archives` | `outrank/archives` | 存档根目录。 |
| `--web-root` | 自动找 `liveboard/web` | `board.html` / `board.js` / `board.css` 所在目录。 |
| `--penalty` | 自动 | 罚时分钟数覆盖（一般不用）。 |
| `--font` | 自动 | 服务端字体文件路径（可选）。 |

健康检查：`GET /health` 返回存档数量与只读标记。

---

## 二、存档目录结构

一场比赛一个目录，`<slug>` 的规则是「题目集 ID-开始时间戳」，例如 `2100000000000000000-20260101120000`：

```text
data/archives/
├── index.json                  # 列表页唯一要读的索引（派生缓存，可重建）
├── 2100000000000000000-20260101120000/
│   ├── contest.json            # 冻结的比赛数据（必需）
│   ├── state.json              # 冻结的展示状态（缺失时写空对象）
│   ├── view.json               # 冻结的视觉配置（live 的 config.json 原文）
│   └── meta.json               # 标题/队伍数/提交数/revealed 等元数据
└── 2100000000000000001-20260102180000/
    └── ...
```

- 目录里**出现 `meta.json` 才算一份完整存档**（写入顺序保证这一点）；
- `revealed=false`：观众视角，站点用存档里的 `contest.json` 按「封榜时刻 + 观众视角」现算封榜快照；
- `revealed=true`：管理员已解榜，站点返回最终榜；
- 所有写盘都是「临时文件 → fsync → `os.replace`」，读侧不会看到半个 JSON。

## 三、存档、解榜、重建索引

以下命令都在仓库根目录执行（Windows 下把 `\` 换成 `/` 也可以）。

### 1. 存档本场

把实时服务的运行目录（里有 `contest.json` / `state.json` / `config.json`）冻成一份存档：

```bat
python -c "import sys; sys.path.insert(0,'outrank'); import archive; print(archive.snapshot_archive(r'liveboard', r'data/archives'))"
```

- 用 GUI 跑实时榜单时，运行目录通常是 `<安装目录>\live`（不是 `liveboard\`），把第一个参数换成它即可；
- 用 `scripts\run-liveboard.bat` 单独跑时，运行目录就是 `liveboard\`；
- 存档不会改动实时数据，实时服务可以继续跑。

### 2. 列出已有存档

```bat
python -c "import sys; sys.path.insert(0,'outrank'); import archive; [print(m['slug'], '已解榜' if m.get('revealed') else '已封存') for m in archive.rebuild_index(r'data/archives')]"
```

`rebuild_index` 会扫描所有含 `meta.json` 的目录并重写 `index.json`，索引丢了也能恢复。

### 3. 解榜 / 取消解榜

```bat
python -c "import sys; sys.path.insert(0,'outrank'); import archive; print(archive.set_revealed(r'data/archives', '<slug>', True))"
```

- `True` = 解榜，公网立刻显示最终榜（`revealed_at` 记为当前时间）；
- `False` = 取消解榜，恢复封榜快照。

只改 `meta.json` 与 `index.json`，不重写比赛数据。

### 4. 校验一份存档

```bat
python -c "import sys,json; sys.path.insert(0,'outrank'); import archive; print(json.dumps(archive.load_meta(r'data/archives','<slug>'), ensure_ascii=False, indent=2))"
```

## 四、部署到服务器

下面用占位符，替换成你自己的值：

- `<SERVER_IP>`：服务器地址
- `<YOUR_DOMAIN>`：外榜域名
- `<SSH_KEY>`：部署用的 SSH 私钥文件
- `<OUTRANK_DIR>`：服务器上的安装目录（例如 `/srv/outrank`）
- `<RUN_USER>`：运行服务的系统用户

### 1. 上传代码与存档

```bash
# 本地执行：把仓库（不含 .git / data / config）和存档传上去
rsync -avz -e "ssh -i <SSH_KEY>" \
    ./    <RUN_USER>@<SERVER_IP>:<OUTRANK_DIR>/
rsync -avz -e "ssh -i <SSH_KEY>" \
    ./data/archives/  <RUN_USER>@<SERVER_IP>:<OUTRANK_DIR>/archives/
```

只需要这几个目录：`outrank/`、`liveboard/`（`outrank.py` 要 import 其中的 `board_core`）、`core/`（排名函数）。`app/` 是 GUI，服务器上不需要。

### 2. systemd

`/etc/systemd/system/outrank.service`：

```ini
[Unit]
Description=ScoreDeck Outrank (read-only archive site)
After=network.target

[Service]
Type=simple
User=<RUN_USER>
WorkingDirectory=<OUTRANK_DIR>
ExecStart=/usr/bin/python3 <OUTRANK_DIR>/outrank/outrank.py \
    --host 127.0.0.1 --port 8099 \
    --archives <OUTRANK_DIR>/archives \
    --web-root <OUTRANK_DIR>/liveboard/web
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now outrank.service
curl -s http://127.0.0.1:8099/health
```

> 服务只绑定 `127.0.0.1`，公网访问统一走 nginx；不要把 8099 直接暴露出去。

### 3. nginx 反向代理 + HTTPS

`/etc/nginx/sites-available/<YOUR_DOMAIN>.conf`：

```nginx
server {
    listen 80;
    server_name <YOUR_DOMAIN>;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name <YOUR_DOMAIN>;

    ssl_certificate     /etc/letsencrypt/live/<YOUR_DOMAIN>/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/<YOUR_DOMAIN>/privkey.pem;

    # 外榜页面、静态资源、只读 API 全部由同一个 Python 进程提供
    location / {
        proxy_pass http://127.0.0.1:8099;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 存档里的校徽/照片会按 /logo/ 路径取，缓存一下
    location /logo/ {
        proxy_pass http://127.0.0.1:8099;
        proxy_set_header Host $host;
        expires 7d;
        add_header Cache-Control "public";
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/<YOUR_DOMAIN>.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

首次签发证书（需要域名已解析到 `<SERVER_IP>`，80 端口可访问）：

```bash
sudo certbot --nginx -d <YOUR_DOMAIN>
sudo certbot renew --dry-run
```

外榜默认挂在域名根路径；页面内部还会用到 `/outrank/<slug>`、`/web/...`、`/logo/...`、`/health`，这些都由同一个 `location /` 覆盖，不需要额外配置。

## 五、赛后解榜流程

1. 比赛结束、确认最终数据无误后，本地执行「存档本场」，得到 `<slug>`；
2. 把 `data/archives/` 同步到服务器（见上一节）；
3. 确认外榜列表能看到这场（此时是**封存**状态，公网看到封榜快照）；
4. 需要公布最终榜时，执行「解榜」：
   - 本地改完再同步：`set_revealed(..., True)` → rsync 整个 archives → `systemctl restart outrank`；
   - 或者直接在服务器上的 `<OUTRANK_DIR>` 里执行同一条 `set_revealed` 命令，然后重启服务；
5. 打开 `https://<YOUR_DOMAIN>/outrank/<slug>` 确认显示「已解榜」的最终榜；
6. 需要恢复封存时，用 `set_revealed(..., False)` 反向操作。

> 也可以把存档、解榜、同步写成自己的脚本/计划任务；核心就是 `snapshot_archive` / `set_revealed` / `rebuild_index` 三个函数。

---

## 六、注意

- **不要把 `archives/`、`cookie.txt`、`config.json` 提交到 Git**；它们都在 `.gitignore` 里。
- 外榜进程只读存档；如果页面 404，先看 `curl http://127.0.0.1:8099/health` 与 `archives/index.json`。
- 存档里的 `view.json` 可能包含当时的奖项/打星名单；对外发布前确认里面没有不该公开的信息。
- 静态字体由 `liveboard/web/fonts/` 提供，部署时整个 `liveboard/web/` 都要上传。
