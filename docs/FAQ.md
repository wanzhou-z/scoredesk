# 常见问题（FAQ）

## 1. 数据拉不全：榜单上只有十几支队伍

先确认三件事：

1. **Cookie 是否有效**：只带 `PTASession` 会 401。必须同时带 `JSESSIONID` 和 `PTASession`；在「数据源」页重新粘贴一次，再点「环境预检」。
2. **是否点过「全量刷新」**：旧版本增量取数只拿第 1 页，后来进群的队会永远进不来。当前版本每轮「拉取数据」都会强制刷新队伍名录（`--refresh-meta`），全量核对不限页数（`--max-pages 0`）。仍不全时，在「服务」页点一次「全量刷新」，或打开榜单加 `?refresh=full`。
3. **题目集 ID 是否正确**：必须是 `/problem-sets/` 后面那串纯数字，填错会拉到别的比赛或空数据。

如果 PTA 上比赛本身处于「封榜」状态，封榜之后的提交本来就不会下发；这不是拉取不全，见下一条。

## 2. 封榜后为什么有些格子显示「待判 / ？」？

PTA 在封榜期间不会把封榜后的判题结果下发给普通账号，数据里只有「已提交、暂无结果」的状态，页面只能显示待判。等 PTA 结束封榜（或管理员用有权限的账号解封）后再刷新，结果才会补全。`?thaw=1` 只是在**已拿到**真实数据时切换展示口径，不能凭空变出 PTA 没下发的判题结果。

## 3. 编译错误（CE）为什么没算进罚时 / 没出现在榜单上？

按 ICPC 规则，CE 不计罚时（`pta_common.py` 里 `COMPILE_ERROR` 的 `penalty=false`），所以它不会让队伍罚时增加，也不会显示成一个错误格。这不是丢数据：`contest.json` 里仍然有这条提交，只是按规则不参与罚时。

## 4. 校徽不显示 / 只有部分队显示

按顺序检查：

1. 校徽目录是否配置正确（「外观」页的「校徽目录」，留空 = 程序目录下的 `校徽/`）；
2. 文件名是否匹配：默认校徽直接叫 `logo.png` / `校徽.png`（或文件名主干为空 / `logo` / `default` / `机构` / `学校`）；专属校徽用「学号」或「姓名」命名最稳，例如 `2026001.png`、`张三.png`；
3. 是否有多层子目录：只扫描一层，图片不要放太深；
4. 生成比赛包时会裁成圆形 PNG 写进 `organizations/<机构ID>/logo.png`，如果原图不是正方形，会先居中裁切；
5. 浏览器端有缓存，换图后强刷一次（`Ctrl+F5`）。

## 5. 端口被占用，服务起不来

- 实时榜单默认 **8791**，外榜默认 **8099**；
- 「服务」页会先检测占用，被占时换一个端口（例如 8765）再启动；
- 自己查占用：`netstat -ano | findstr :8791`，再用任务管理器按 PID 结束，或直接换端口；
- 不要在同一个端口上同时起两个实时榜单实例。

## 6. 换一台机器 / 跨机器部署要改什么？

- 复制**整个程序目录**（或整个仓库），不要只拷 exe；
- 新机器要装 Python 3.9+；要滚榜还要 Java 17+ 和 Resolver；
- `config.json`、`cookie.txt`、`history.json` 是每台机器自己的，换机器需要重新填题目集 ID 和 Cookie；
- 路径相关的配置（照片/校徽/字体）如果写的是绝对路径，换机器后要改成新路径或留空用默认目录；
- 外榜跨机器部署见 `docs/外榜部署.md`。

## 7. 榜单页中文显示成方框

缺中文字体。把任意含中文的 TTF/TTC 放到 `tools/fonts/`（程序会优先找 `MicrosoftYaHei.ttc`），或在「外观」页手动指定字体文件。`simhei.ttf` 虽然含中文，但缺榜单格子用的排版符号（`−` `•` `⁄`），会把罚时渲染成方框，不推荐。

## 8. OBS 里背景不透明 / 有控件

给 OBS 的地址加 `?overlay=1`。该模式会隐藏标题栏、控制条和页脚，并把页面背景设为透明；OBS 的浏览器源本身也要勾选「允许透明」。

## 9. 点「启动」后服务起不来

1. 确认 `python --version` 能看到版本号（3.9+）；
2. 看「服务」页的日志，或程序目录下 `logs/` 里的文件；
3. 打包版还需要本机有 Python 解释器（实时取数进程要跑 `pta_fetch.py`）；
4. 端口被占用时按第 5 条处理。

## 10. 外榜页面 404 / 列表是空的

- 确认 `archives/` 下有含 `meta.json` 的场次目录，或执行一次 `archive.rebuild_index(...)` 重建索引；
- 确认启动参数 `--archives` 指向了正确的目录；
- `curl http://127.0.0.1:8099/health` 应返回 `{"ok": true, ...}`；
- nginx 反代时确认 `/outrank/`、`/web/`、`/logo/`、`/health` 都在同一个 `location /` 下。

## 11. 解榜后页面还是封榜快照

`set_revealed(..., True)` 只改 `meta.json` / `index.json`，确认：

1. 改的是**服务器上**正在被服务读取的那份 `archives/`（不是本地副本）；
2. 改完重启了外榜服务（`systemctl restart outrank`）；
3. 浏览器缓存：强刷一次，或看 `/outrank/<slug>` 页面上的「已解榜」标记。

## 12. 能把 Cookie / 比赛数据提交到 Git 吗？

不能。`cookie.txt`、`config.json`、`contest.json*`、`history.json`、`logs/`、`archives/` 都在 `.gitignore` 里；它们包含登录态或真实比赛数据，只应留在本机。

## 13. 遇到问题怎么反馈

欢迎在本仓库开 Issue（可以直接用 `.github/ISSUE_TEMPLATE/bug_report.md` 里的模板）。为了能定位问题，请尽量带全这几项：

1. **系统版本**：例如 Windows 11 23H2 / Ubuntu 24.04；
2. **浏览器版本**：如果是榜单页的问题；
3. **用的是哪个功能**：实时榜单 / 赛后滚榜 / 外榜（存档 / 解榜 / 只读站点）；
4. **复现步骤**：点了什么、打开的是哪个网址；
5. **期望结果与实际结果**；
6. **截图或日志**：日志一般在程序目录 `logs/` 下。

> **贴日志 / 截图前请先删掉 Cookie、学号、姓名等隐私信息。** 尤其是 `cookie.txt` 的内容和 `contest.json` 里的队伍名单，不要直接贴到公开的 Issue 里。
